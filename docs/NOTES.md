# Notes

Real problems I ran into while doing the task, in order.

## 3 November 2026

- **Python 3.9 and the latest Playwright do not mix.** The task says Python 3.9+, but Playwright for Python dropped 3.9 in 1.61 (June 2026): `pip install playwright` on 3.9 silently installs an older version than on 3.12. I pinned `playwright==1.60.0`, the last release that supports 3.9, so every machine gets the same Playwright and the same Chromium build. CI runs the tests on 3.9, 3.12 and 3.14.
- **Looked at the reference video first.** I dumped frames of `output.webm` with Playwright itself (a `<video>` element, seek, screenshot), because there is no ffmpeg on my machine. That gave the target look: callout under the search box, white arrow, yellow circle behind it.
- **The first submit button is hidden.** The first run failed on `form button[type="submit"]`: on DuckDuckGo it matches a 0 px wide button, and the visible "Search" button appears in the suggestion box only after typing. I take the first visible match now (`>> visible=true`).
- **DuckDuckGo blocks headless Chromium.** The second run typed the query, clicked the button and then waited 30 s for nothing: the frames showed "Unexpected error. Please try again", the URL was `static-pages/home-error/418.html`. I compared in one script: headless gives the error page, a normal window gives results. So the browser runs with a window by default. I did not try to disguise the headless browser.
- **On my PC the bundled Chromium did not start with a window** ("side-by-side configuration is incorrect"). The same files started fine from another folder; only folders inside `AppData\Local` (except `Temp`) failed. This is my Windows build, not the project, so I kept the browsers in `C:\Users\USER\ms-playwright` and set `PLAYWRIGHT_BROWSERS_PATH` for my runs. CI on a clean Ubuntu installs Chromium the normal way.
- **The ripple was there, but not in the video.** Tests said the ripple element appears, and the frames showed almost nothing. Two reasons, found by cutting the frames around each click: the ripple had the same size as the yellow circle and hid behind it, and the search click starts a navigation, so the page was gone before the ripple was painted. Now the ripple is a strong orange ring that grows a bit past the circle, and Python starts it 0.3 s before the real click.
- **The cursor made a detour to the first result.** The results list was still shifting while the cursor moved, so it aimed at an old position and had to turn. Now it waits until the target stops moving, and checks after the move that it is still on it.
- **Up to 10 s of an empty white screen while the results load.** The results page stays blank until DuckDuckGo renders it, and my cursor waited for `DOMContentLoaded` to appear. Init scripts run before `<html>` exists, so I mount the cursor with a `MutationObserver` as soon as `<html>` appears. The page is still white for a moment, but the cursor stays on screen.
- **The page language followed my computer.** The first videos had the Russian DuckDuckGo interface. The CSV has a `Language` column, so it is now the browser locale; anything that is not a language code falls back to English.
- **A test was wrong, not the code.** `page.evaluate` returns the promise of `ShowCallout` and waits for it, so the test looked for the callout after it was already gone. The test now starts the callout without waiting.
- **The first result is someone else's site.** For Manchester it was designrush.com, which shows a Cloudflare "security verification" page. The click is correct, the video just ends on that page. Not something to work around.
